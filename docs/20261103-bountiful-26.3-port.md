# Bountiful 26.3 Port (Fabric)

**Date:** 2026-11-03
**Branch:** `26.3` in `kylerm42/Bountiful`, `kylerm42/Kambrik`, `kylerm42/Percale` and `kylerm42/Mod-Build-Logic`
**Mod version:** Bountiful `8.0.0-beta.2`
**Supersedes:** [20260327-bountiful-1.21.11-fabric-port.md](20260327-bountiful-1.21.11-fabric-port.md) as the current port document.

## 1. Purpose and scope

This document describes the port of Bountiful and its libraries (Kambrik, Percale) to Minecraft 26.3 on Fabric.
The port is a rebase onto upstream's 26.1.2 port (`ejektaflex/*`), with the fork's gameplay changes and fixes
re-applied by hand and the result moved to 26.3.

In scope:

- Fabric on Minecraft 26.3: build, dedicated server, client, gametests, client gametests.
- Bountiful, Kambrik, Percale and the shared `build-logic` plugins.

Out of scope:

- **iChunUtil.** Upstream has no changes to it and Bountiful does not reference it.
- **NeoForge.** The `:neoforge` modules of Percale and Kambrik compile on 26.3. **Bountiful's `:neoforge` module does
  not compile on 26.3**, so a plain root `./gradlew build` in `Bountiful` fails. Known errors:
  - `WandererTradesEvent` no longer exists (the NeoForge decree trades use it).
  - `Minecraft.screen` moved to `minecraft.gui.screen()` (NeoForge client code).

  Always build Bountiful with `:fabric:build`. NeoForge was not fixed because it is not used by this fork.
- Existing 1.21.11 worlds are not a migration target. Use fresh worlds.

## 2. Workspace layout and setup from scratch

### Layout

All four repositories are siblings in one directory. Bountiful's `settings.gradle` and each repository's
`multiloader-settings` plugin expect these relative paths (`../build-logic`, `../Kambrik`, `../Percale`).

```
minecraft/
├── build-logic/   kylerm42/Mod-Build-Logic, branch 26.3
├── Percale/       kylerm42/Percale, branch 26.3
├── Kambrik/       kylerm42/Kambrik, branch 26.3
└── Bountiful/     kylerm42/Bountiful, branch 26.3
```

### Clone

```sh
mkdir minecraft && cd minecraft
git clone -b 26.3 git@github.com:kylerm42/Mod-Build-Logic.git build-logic
git clone -b 26.3 git@github.com:kylerm42/Percale.git
git clone -b 26.3 git@github.com:kylerm42/Kambrik.git
git clone -b 26.3 git@github.com:kylerm42/Bountiful.git
```

The `26.x` branches of the same repositories hold the 26.1.2 baseline (upstream code plus the fork changes before
the 26.3 bump). They build only with `build-logic` checked out on `26.x`, because `platform.properties` holds the
Minecraft version.

### JDK 25

Minecraft 26.3 requires Java 25 (Mojang version manifest `javaVersion.majorVersion=25`). With
[mise](https://mise.jdx.dev):

```sh
mise install java@temurin-25
export JAVA_HOME="$HOME/.local/share/mise/installs/java/temurin-25.0.5+8.0.LTS"   # adjust to the installed version
export PATH="$JAVA_HOME/bin:$PATH"
```

Any JDK 25 works; `JAVA_HOME` must point to it. `gradlew` is not marked executable in the repositories, so run it
with `sh ./gradlew`. The wrappers use Gradle 9.8.2 (Loom 1.19.3 requires Gradle 9.8 or newer).

### Build order

Bountiful depends on `kambrik-fabric-26.3` and `percale-fabric-26.3`, and Kambrik depends on Percale. These
libraries are resolved from `mavenLocal()`, so publish them in this order:

```sh
cd Percale  && sh ./gradlew :fabric:build publishToMavenLocal
cd ../Kambrik  && sh ./gradlew :fabric:build publishToMavenLocal
cd ../Bountiful && sh ./gradlew :fabric:build
```

Output jar: `Bountiful/fabric/build/libs/bountiful-fabric-8.0.0-beta.2.jar`. Percale's unit tests run as part of
`build` (`:common:test`); Bountiful's unit tests run with `:common:test`.

**Composite-build caveat.** `Bountiful/settings.gradle` calls `includeBuild('../Kambrik')` and
`includeBuild('../Percale')`, but Gradle does not substitute them. Gradle matches substitutions by project identity
(`io.ejekta.kambrik:fabric`), while the dependency coordinates are `kambrik-fabric-26.3` (the publication
`artifactId` is `<mod>-<module>-<mc_version>`). `publishToMavenLocal` is therefore required after every change in
Percale or Kambrik. An explicit `dependencySubstitution` per module in the settings plugin would fix this; it was
not done.

`publishToMavenLocal` in Percale and Kambrik also publishes the `:neoforge` module, which compiles there. For
Bountiful use `:fabric:build`, never the root `build`.

### Running

Run all of these in `Bountiful` unless noted.

| Goal | Command | Notes |
|---|---|---|
| Dedicated server | `sh ./gradlew :fabric:runServer` | Run dir `fabric/runs/server`. Accept the EULA in `fabric/runs/server/eula.txt` on first start. |
| Client | `sh ./gradlew :fabric:runClient` | Run dir `fabric/runs/client`. Dev-environment auth/Realms 401 errors are expected. |
| Server gametests | `sh ./gradlew :fabric:runGameTestServer` | Run dir `fabric/runs/gametest`. Report: `fabric/build/reports/game_test/results.xml`. |
| Client gametests | `sh ./gradlew :fabric:runClientGameTest` | Needs a display. Run dir and screenshots: `fabric/build/run/clientGameTest/screenshots`. Not part of `build`. |
| Common unit tests | `sh ./gradlew :common:test` | Includes `DepthSolverPricingTest` and `ChaosDefaultsTest`. |

Gradle properties defined in `Bountiful/fabric/build.gradle` (pass with `-P`):

| Property | Effect |
|---|---|
| `-PnoOptionalMods` | Leaves ModMenu and Cloth Config out of the dev runtime classpaths (to test startup without them). |
| `-PnoTrekTests` | Leaves Lithostitched and Trek out of the dedicated gametest server. |
| `-PnoTatTests` | Leaves Towns and Towers and Cristel Lib out of the dedicated gametest server (Lithostitched stays unless `-PnoTrekTests` is also set). |
| `-PvillageSamples=N` | Samples per village structure in the `villageBoardsHonorGenFrequency` gametest (default 24). Passed as `-Dbountiful.villageSamples`. |
| `-PextraMods=/dir` | Adds every `.jar` in `/dir` to the gametest server and to `:fabric:runServer` (`-Dfabric.addMods`). |

The gametest server loads Lithostitched and Trek (`trekTestMods` configuration, from the Modrinth Maven) unless
`-PnoTrekTests` is set. The village board tests need both: Lithostitched replaces vanilla's jigsaw placement for
every jigsaw structure, so the quota must be tested with it installed.

## 5. Upstream baseline versus fork changes

### Based on upstream 26.1.2

Upstream ported to 26.1.2 between 2026-04-10 and 2026-04-20 (Bountiful `upstream/dev` `8.0.0-beta.1`, Kambrik
`upstream/dev`, Percale `upstream/master`). The 26.x branches start from those heads. The Identifier rename, recipe
display API, ValueInput/Output, GUI extract API, data-driven trades, Cloth Config screen (NeoForge) and the global
board state come from upstream.

Upstream's Bountiful `dev` head did not compile on 26.1.2 as pushed. The fixes in this fork are minimal
(`ExtMisc.kt` duplicate import, `BountyTypeEntity` `ValueOutput`, `defaultBlockState()`, access widener class names,
`jar` duplicate strategy).

### Fork-specific changes

**Build (`build-logic`, Percale, Kambrik)**

- Platform values for 26.x, no-remap Loom, Gradle 9.8.2, no Parchment, no refmap.
- Publication artifact ids are `<mod>-<module>-<mc_version>`; version gets a `.${snapshot_build}` suffix for
  snapshots.
- `src/client/{java,resources}` of Fabric modules are compiled into the main source set. Before this fix, the client
  entrypoints were missing from the jars and the client crashed with `ClassNotFoundException`
  (see `build-logic/README.md`).
- Percale tests were adapted to the 26.x API (`parseCompoundFully`, nullable `serialize`).

**Gameplay and fixes (Bountiful)**

- **`chaos.mode`** (`OFF` / `ON` / `COMBINED`) replaces upstream's `dbg.enabled`, which was only used for chaos and
  has been removed. `ON` replaces all normal pools and decrees with the generated chaos pool and decree.
  `COMBINED` adds the chaos pool and decree alongside the normal ones. The mode takes effect on server start.
- **DepthSolver fixes:** the unsolved-ingredient counter starts at the ingredient count, so recipes with an
  unresolvable input are rejected instead of priced near zero (empty option sets are not filtered, so an ingredient
  with no options also rejects the recipe); `ignoreSet` items are excluded from the pool; unresolvable items are cached
  (`unresolvableCache`; without it the solver runs exponentially and the server watchdog kills the server). Recipes and
  ingredient options are sorted by id so results are stable across runs.
- **Chaos defaults seeding and merge:** curated prices are bundled in the jar
  (`data/bountiful/chaos/bountiful-chaos.default.json`) and merged into the user's `bountiful-chaos.json` on every
  start (see section 6). `ignoreRegex` now excludes items from the pool and the config.
- **Trek compatibility:** eight Lithostitched worldgen modifiers in
  `data/bountiful/lithostitched/worldgen_modifier/trek/` (`fabric:load_conditions` for `mr_trek`) plus an empty
  `worldgen/processor_list/plains.json`.
- **Decree trades on wandering traders (Fabric):** four data-driven villager trades
  (`data/bountiful/villager_trade/wandering_trader/decree_{1..4}.json`, 2/3/5/9 emeralds for 1 to 4 decrees),
  appended to `#minecraft:wandering_trader/common`, and the `bountiful:random_decree` loot function
  (`RandomDecreeFunction`). Behavior differs from 1.21: four fixed tiers instead of one trade with a random rank.
  A trader has roughly a 25% chance to offer at least one decree. The files are in the `fabric` module because the loot
  function is registered only there.
- **Config screen (Fabric):** Cloth Config screen opened from ModMenu, including a `chaos.mode` selector. Cloth Config
  is optional; only `BountifulConfigScreen` references it.
- **Boards per village:** `StructureGenerateMixin` (`@WrapMethod` on `Structure.generate`) sets a per-thread quota
  derived from `villageGenFrequency`, seeded by world seed and start chunk. `StructureTemplatePoolMixin` (vanilla) and
  `LithostitchedTemplatesMixin` (Lithostitched's template shuffle, applied only when Lithostitched is present)
  filter the candidate list, and `PoolElementStructurePieceMixin` counts boards as pieces are created. This replaces
  upstream's `JigsawAddPiecesMixin`, `JigsawPlacementMixin` and `JigsawPlacerAccessor`, which never ran when
  Lithostitched is installed (it replaces `JigsawPlacement.addPieces` for every jigsaw structure).
- **Content sync for the analyzer:** `ContentSyncChunk` sends decrees and pool entries from a dedicated server to the
  client when `/bo util analyzer` or `/bo util editor` is used. It is skipped when the client hosts the server.
- **Completion toast fix:** the server now sends `OnBountyComplete` on turn-in (`BountyStack.tryCashIn`) and
  `BountyItem.inventoryTick` polls for completed item bounties. Clientbound payloads are registered in the common
  initializer on both sides.
- **Other fixes:**
  - Taken bounties were offered again (`BoardBlockEntity.maskMatching`).
  - Container click crash for bounties with objective data (Percale `Codec.toSerializer` accepts any `DynamicOps`).
  - Decree placement NPE.
  - Board item name (`useBlockDescriptionPrefix()`).
  - `minecraft:chain` renamed to `minecraft:iron_chain` in a pool.
  - Entity preview crash in board GUI (Kambrik `KGuiDsl.livingEntity` sets a display entity id of -1).
  - Invisible DSL text with alpha 0 colors.
  - Item tooltip anchor in the Kambrik DSL.
  - Analyzer refresh and empty-state handling.
  - Compostable chances restored through the item component.
  - Block state keys (`id`/`properties`) in processor lists.
- **26.3 API migrations:** SDL3 input (1-based mouse buttons, SDL scancodes in `KambrikModifiedBind.Key`),
  `advancements.triggers`, `TeamColor`, data-driven carvers/features, Fabric API's own `@GameTest` annotation.
- **Tests:** `DepthSolverPricingTest`, `ChaosDefaultsTest`, 15 server gametests, `BountifulClientGameTest`
  (board, analyzer, editor, toast and config screen).

Not re-applied from the 1.21.11 branch: 1.21.11 API changes, item-tag naming (upstream equivalent), `Codec.java`,
the fork's `items/*.json` and `CUSTOM_MODEL_DATA`.

## 6. Configuration reference

All files are in `config/bountiful/` of the game or server directory. The config is read at startup and rewritten
by the mod (Kambrik `KambrikConfigFile`, parse failure mode `LEAVE`). Unknown keys, such as a leftover
`dbg`, are ignored and removed on the next write.

### `bountiful.json`

| Key | Type | Default | Meaning |
|---|---|---|---|
| `board.updateFrequencySecs` | int | `45` | Seconds between board refreshes. |
| `board.villageGenFrequency` | float | `1.0` | Boards per generated village. `0.0` = none, `1.0` = exactly one, `2.5` = two plus a 50% chance of a third. Requires a restart and applies to newly generated villages only. |
| `board.canBreak` | boolean | `true` | Whether boards can be broken. |
| `board.globalBoardState` | boolean | `false` | When `true`, all boards share one bounty state. |
| `bounty.flatBonusTimePerBountyInSecs` | int | `0` | Seconds added to every bounty's time limit. |
| `bounty.shouldHaveTimersAndExpire` | boolean | `true` | Whether bounties have timers and expire. |
| `bounty.fillerDifficultyModifierPercent` | int | `0` | Percentage added to the worth that filler objectives must cover. |
| `bounty.allowDecreeMixing` | boolean | `true` | Whether bounties may combine entries from different decrees. |
| `bounty.reverseMatchingAlgorithm` | boolean | `false` | Generate rewards first and objectives to match, instead of objectives first. |
| `bounty.initialCountPreference` | `{min, max}` | `{1, 2}` | Range of initial (non-filler) entries per bounty. |
| `bounty.fillerCountPreference` | `{min, max}` | `{1, 2}` | Range of filler entries per bounty. |
| `bounty.fillerCurrencyPool` | string or `null` | `null` | Id of a pool with `currency: true` used for filler. A missing or non-currency pool logs a warning and is ignored. |
| `client.showCompletionToast` | boolean | `true` | Show the toast when a bounty's objectives are complete or rewards are received. |
| `chaos.mode` | `OFF` / `ON` / `COMBINED` | `OFF` | Chaos Mode (below). |
| `general.dataPathsToExclude` | list of strings | `["bounty_pools/bountiful/example_pool", "bounty_pools/*/another_example", "bounty_decrees/other/*"]` | Data paths excluded from loading; `*` is a wildcard. |

The `chaos.mode` option:

- `OFF`: Chaos Mode is disabled; only normal decrees and pools are used.
- `ON`: all normal pools and decrees are replaced by the chaos pool and one chaos decree.
- `COMBINED`: the chaos decree and pool are registered alongside the normal ones.

### Chaos files

Chaos Mode runs on `SERVER_STARTED`. It builds a pool from item prices that it derives from recipes.

- **`bountiful-chaos.json`** (user-editable):
  - `required`: prices of terminator items, meaning items with no recipe (raw materials).
  - `optional`: items that cannot be priced from recipes. A non-null value is a fixed price.
  - `matching.tag`, `matching.regex`: price every item in a tag or matching an id regex.
  - `matching.ignoreRegex`: `{ "<regex>": true }` excludes matching items from the pool and from the config.
- **`bountiful-chaos-info.json`** (generated, informational): `deps`, `unsolvedList`, `redundant`. Do not edit.

How prices work:

1. An item's price is the fixed price from `required`/`optional`, or the price of a matching `regex`/`tag` rule
   (regex first, then tag).
2. Otherwise the solver prices the item from its recipes: the sum of the first priceable option of every ingredient,
   divided by the recipe's result count. The cheapest recipe wins. A recipe with any unresolvable ingredient is
   rejected. Cycles and recursion deeper than 24 levels are treated as unresolvable.
3. Each priced item becomes a pool entry with `unitWorth` equal to its price, an amount range of `1` to its max
   stack size, and a rarity from the item's rarity (stack size 1 with common rarity counts as uncommon).

**`null` means unpriced.** An item whose price is `null` is not in the pool. The solver writes `null` for every
unresolved terminator (`required`) and unpriceable item (`optional`). Setting a number makes the item priceable and
lets recipes that use it be priced.

Merge from defaults (every start, before solving): the jar bundles a curated file. For `required`/`optional`, a
missing or `null` entry takes the bundled price when that price is non-null. Values the user set are never changed.
For `matching.tag`, `regex` and `ignoreRegex`, bundled keys that are missing are added and nothing is removed or
changed. Bundled prices are skipped when the user's `regex` rules already price the id, or an enabled `ignoreRegex`
rule excludes it. Merging twice changes nothing. A missing file is created and seeded the same way. The result is
written back, so the file always shows the effective data.

Startup log lines: `Chaos: merged N required and M optional prices, ...`, `Chaos: P priced items in the pool`,
`Chaos: U items unpriced, see config/bountiful/bountiful-chaos.json (entries with null)`.

Reference result (dedicated server, 26.3, bundled defaults, vanilla only): 1014 priced items in the pool, 424
unpriced, identical across repeated runs.

## 7. Known issues and gaps

- **Villager POI memory and walk-to-board.** Upstream's wiring is incomplete (`POI_MEMORIES` is immutable in 26.1.2).
  Villagers may not walk to boards. This is not a regression from upstream and has not been fixed. `BountifulTaskMixin`
  loads and its targets exist in 26.3, but it was not exercised with a live villager.
- **Trek mushroom village defect.** Its pools reference nonexistent `minecraft:village/mushroom/*` pools, so it
  generates only the town center (one piece) and has no boards. This is a Trek defect. Zombie-variant villages have
  no gazebo, so they have no boards either.
- **Towns and Towers compatibility (1.13.13).** Modifiers in `data/bountiful/lithostitched/worldgen_modifier/towns_and_towers/`
  add the gazebo to the `houses` pool of 19 villages: badlands, birch forest, flower forest, forest, jungle, meadow,
  mushroom fields, old growth taiga, snowy taiga, sparse jungle, swamp, wooded badlands, and the exclusives classic,
  iberian, mediterranean (`houses/regular`), nilotic, rustic, swedish, tudor. Nilotic uses the variant
  `bounty_gazebo_floor` (T&T connects its houses with `minecraft:building_floor`; all others use
  `minecraft:building_entrance`). Gaps and limits:
  - No board in villages without a `houses` pool (beach, grove, snowy slopes, sunflower plains, savanna plateau), the
    ocean, piglin and wandering trader camp villages, outposts, `mimic_desert` and `wreckage_ocean`.
  - Jar installs only. The standalone T&T datapack has no mod id, so no board is added. (`fabric:registry_contains`
    on the pool crashes registry loading when Lithostitched is present without the pools, so it is not used.)
  - Placement on slopes and at ponds is not verified visually; the gazebo is rigid and may float or clip.
  - Lithostitched logs an upstream warning for a missing T&T pool (`sparse_jungle_polynesian/villager_village_chief`).
  - Bountiful does not use the `#minecraft:village` tag, which T&T extends.
  - Tested by the gametests `townsAndTowersBoardsHonorGenFrequency` and `townsAndTowersOutOfScopeStructuresHaveNoBoards`
    (exactly 1 board at frequency 1.0 in every in-scope village, 2 to 3 at 2.5, 0 at 0, 0 in out-of-scope structures).
- **Trek in-world confirmation.** Board counts per Trek village are validated by gametests (exactly one at frequency
  1.0). One earlier Trek run logged `Block-attached entity at invalid position` warnings during chunk generation. It
  did not recur and is probably Trek structure data; it was not investigated.
- **Dedicated-server analyzer sync is untested with a real remote client.** `ContentSyncChunk` is covered by build and
  code review only. The earlier hard-coded `fletcher` decree lookup in `AnalyzerScreen` (which would fail on a
  dedicated-server client) was removed.
- **NeoForge does not compile** for Bountiful on 26.3 (section 1). The NeoForge config screen is a separate, untouched
  copy.
- **Chaos pool contents.**
  - The solver's `unresolvableCache` is path dependent: an item that fails only because of a cycle on the current
    path is cached as unsolvable. Recipes and options are now sorted, so repeated runs on the same game content are
    identical, but the pool can still differ between Minecraft versions and mod sets.
  - 424 items stay unpriced in a vanilla install. Set a price in `optional` or add a `regex`/`tag` rule to include
    them.
- **CTOV (village overhaul mod) has no 26.3 build,** so compatibility with it has not been tested.
- **Wandering trader decrees** appear less predictably than in 1.21 (four fixed tiers in a 75-entry pool).
  Tuning options: the tag (`uncommon` instead of `common`), the number of tiers, or a `merchant_predicate`.
- **Percale encoding.** Nullable fields now encode as empty values instead of being omitted, and `toCodec()` respects
  `prefix`. Existing world or config data may round-trip differently; only fresh worlds were tested.
- **Input constants.** `KambrikModifiedBind.Key` values are SDL scancodes on 26.3. Key-binding code that stores
  GLFW codes needs checking.
- **Not exercised by a human or test:** board hover tooltips on entries, board click interaction beyond the client
  gametest, `-PextraMods` with real third-party jars, an actual dedicated server with a remote client, and
  `/bo util editor` save on a dedicated server.
- **Fabric `compat-*` builtin resource packs** point to directories that do not exist. This is an upstream issue
  noted in the plan; it was not re-verified.
- **`jar` `duplicatesStrategy = EXCLUDE`** in `fabric/build.gradle` is a workaround for a duplicate
  `fabric.mod.json` entry.
- The `build-logic` fork's `origin` remote in the author's checkout uses HTTPS; pushes were made over
  `git@github.com:kylerm42/Mod-Build-Logic.git`.

## 8. Troubleshooting

**`ClassNotFoundException` for `BountifulClient` or `KambrikClientMod` at client start.** The client entrypoint class is
missing from the jar. Use `build-logic` branch `26.3` (or a later commit than `ef95a33`) and rebuild and
republish Kambrik (`publishToMavenLocal`) and Bountiful. Build-logic and the consuming repositories must be on the same
branch (`26.3`).

**Mixin failure after a Lithostitched update.** The Lithostitched mixin is declared with `require = 0` and targets the
internal `LithostitchedTemplates.shuffle`. If an update renames it, the mixin is skipped silently and the boards-per-village
quota stops applying in Lithostitched-based villages (villages may have 0 to several boards). The gametest
`villageBoardsHonorGenFrequency` detects this: run `:fabric:runGameTestServer` after changing `lithostitched_version`
in `Bountiful/gradle.properties` and update `LithostitchedTemplatesMixin` to the new method.

**Empty chaos pool.** The pool is empty when no priced items exist. Check `config/bountiful/bountiful.json` (`chaos.mode`
is not `OFF`) and the log lines `Chaos: P priced items in the pool` and `Chaos: merged ...`. The curated prices are
merged on every start; if `required` terminators are all `null`, delete the stale `bountiful-chaos.json`, or fill in
prices, and restart. A change to `chaos.mode` needs a world or server restart.

**`platform.properties not found`.** `build-logic` is not checked out as a sibling directory. See
section 2.

**`Could not find io.ejekta.kambrik:kambrik-fabric-26.3`.** Run `publishToMavenLocal` in Percale, then Kambrik.
